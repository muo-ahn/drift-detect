# drift-detect 설계안 v1

> README 가 "왜/무엇을" 이라면, 이 문서는 **"목적에 비추어 무엇을 만들고 무엇을 만들지 않는가"** 다.

---

## 1. 목적

> **이슈·문의로 들어오는 것을 최대한 자동화하고, 설계와 리팩터링에 주의를 전부 쓴다.**

drift-detect 는 목적이 아니라 **수단**이다. 자동화 루프를 신뢰할 수 없으면 사람이 매 단계를 확인해야 하고,
그러면 주의가 전혀 절약되지 않는다. **감사는 자동화의 전제조건**이라서 만든다.

이 문장이 이후 모든 판단의 기준이다. 아래 모든 설계 결정은 여기서 연역된다.

---

## 2. 평가 함수

목적을 측정 가능한 형태로 옮기면:

```
maximize   설계·리팩터링에 쓴 주의 / 전체 주의
```

주의를 소비하는 항목은 넷이다.

| # | 항목 | 감사 체계와의 관계 |
|---|---|---|
| 1 | 작업 지시 | 불가피. 대상 아님 |
| 2 | 중간 확인 | **자동화 대상** |
| 3 | 경보 대응 | 감사 체계가 **생성**하는 비용 |
| 4 | 사후 수습 | 감사 체계가 **절감**하는 비용 |

```
drift-detect 의 순가치 = (4 절감분) − (3 생성분)
```

**경보가 수습보다 비싸면 순손실이다.** 탐지율이 아니라 이 부등식이 성패를 가른다.

### 여기서 바로 따라나오는 것 — 오탐/미탐 비대칭

| | 즉시 비용 | 지연 비용 | 신뢰 영향 |
|---|---|---|---|
| **오탐** (정상인데 걸림) | 주의 소비 **즉시** | — | **경보를 끄게 만듦 → 체계 사망** |
| **미탐** (드리프트인데 통과) | 0 | Tier 2 hand-off 게이트에서 포착 | 낮음 |

미탐에는 **백스톱이 있고**, 오탐에는 없다.
→ **의심스러우면 통과시킨다.** 확실한 것만 차단한다.

이것이 "최대한 잡는다" 는 직관을 명시적으로 기각하는 근거다.

## 3. 성공 기준

탐지율은 지표가 아니다. 목적을 직접 재는 것만 쓴다.

| 지표 | 의미 | 목표 |
|---|---|---|
| **무개입 완주율** | 계획 확정 → hand-off 까지 사람 개입 0인 작업 비율 | **북극성.** 상승해야 함 |
| 사람 도달 경보 | 강도 2(ask)가 발생한 횟수 | **예산 ≤ 3회/일** |
| 사후 수습 사건 | 병합 후 발견된 범위 이탈 | 감소해야 함 |
| 판정 정확도 | verdict 대비 사후 인간 판정 일치율 | 관측만. 게이트 아님 |

**경보 예산을 초과하면 체계가 스스로 강등한다** — 임계를 완화하거나 escalation 을 끄고 알린다.
사람이 경보를 끄게 두지 않는다. 끄는 순간 되돌아오지 않는다.

## 4. 비목표

| 안 하는 것 | 이유 |
|---|---|
| 코드 품질 리뷰 | code-review 사이클의 몫 |
| 보안 취약점 탐지 | security-reviewer 의 몫 |
| 전수 드리프트 탐지 | 오탐 비용이 이득을 넘김 (§2) |
| 에이전트 설득·교육 | 술어는 설득하지 않는다. 차단하거나 통과시킨다 |
| 계획 품질 평가 | 계획이 나쁘면 계약이 없을 뿐, 그건 사람의 판단 영역 |

## 5. 구성요소

```
 implementation-plan.md §5 contract 블록
            │
            ▼  [C1] 컴파일러 (세션 시작 / 파일 변경 시)
   .claude/state/contract.json
            │
            ├──────────────▶ [C2] 술어 엔진  (PostToolUse, 동기, 0비용)
            │                      │ 의심 시 요청만 write, 대기 없음
            │                      ▼
            │                [C5] 감사 프로세스 (out-of-process, 비동기)
            │                      │ verdict write
            │                      ▼
            └──────────────▶ [C3] verdict 저장소 (경로 앵커, TTL)
                                   │
                                   ▼
                             [C4] 액추에이터 (PreToolUse / Stop)
```

| | 구성요소 | 책임 | 실패 시 |
|---|---|---|---|
| C1 | 컴파일러 | plan §5 블록 → `contract.json` | 계약 없음으로 폴백 |
| C2 | 술어 엔진 | 계약 대조, 위반 분류 | 통과 |
| C3 | verdict 저장소 | 경로 앵커 판정 + TTL | 통과 |
| C4 | 액추에이터 | deny / ask / block 집행 | 통과 |
| C5 | 감사 프로세스 | 술어로 불가능한 판정 | 통과 (미탐은 Tier 2 가 받음) |

**모든 구성요소가 fail-open 이다.** 고장난 감사 체계가 작업을 멈추면,
§2 의 부등식에서 3번(경보 대응)이 무한대가 된다. 목적에 정면으로 반한다.

## 6. 상태 레이아웃

```
.claude/state/                          # gitignored (.gitignore:251)
├── contract.json                       # 컴파일된 계약
├── contract.meta.json                  # 소스 경로·mtime·해시 (재컴파일 판단)
├── verdicts/
│   └── <target 해시>.json              # 경로 앵커 판정 + TTL
└── audit/
    ├── requests/<id>.json              # 감사 요청 큐
    └── log.jsonl                       # 전체 판정 로그 — 컨텍스트 아님, 사후 검증용
```

worktree 는 각자 자기 작업 트리를 가지므로 상태가 자연 격리된다.
메인 트리에서 본 worktree 내부는 `.claude/worktrees/` 로 이미 무시된다.

## 7. verdict 생애주기

```
1. C2 가 allow_paths 밖 Edit 관측
2. C2 → requests/ 에 요청 write, 즉시 반환  (세션 대기 없음)
3. C5 가 비동기로 판정: 계약서 + diff + JSONL 창
4. C5 → verdicts/<hash(target)>.json write
5. 다음 PreToolUse 에서 C4 가 target 매치 확인 → action 집행
6. 교정되거나 TTL 만료 시 소멸
```

**턴이 아니라 경로에 앵커링한다.** 비동기라 판정이 돌아올 때 세션은 이동해 있다.
경로 앵커는 경쟁 조건에 지지 않는다.

## 8. 단계별 구현

각 단계는 **다음 단계로 넘어갈 근거를 실측으로 만든다.**

### M0 — 계약 컴파일러 — **완료 (2026-09-14)**
- 산출: `C1` (`src/drift_detect/`), `contract.json` / `contract.meta.json`, 테스트 55건
- 종료 기준 충족: 실제 계획 문서(`feat/meta_acc_delete_callback`)의 산문 §5 에서 경로 7건을
  자동 추출해 컴파일된 계약과 대조 → 7/7 허용, 범위 밖 대조군 3/3 거부

**구현 중 잡은 결함 3건은 전부 "테스트 전량 통과 + 완료 보고" 이후에 발견됐다.**

| # | 결함 | 보고 시점 | 발견 경로 |
|---|---|---|---|
| 1 | 미지 키가 `scope` 앞에 오면 계약 전체 유실 (전방 호환 붕괴) | 34/34 PASS | 실계약 스모크 |
| 2 | 정책 파일 malformed 시 완전 침묵 | 43 PASS | malformed 주입 |
| 3 | 가짜 루트 탐지가 레포 디렉터리 이름에 의존 → worktree 에서 전부 무사통과 | 45 PASS | 디렉터리 이름 변주 |

3번은 메인 트리에서만 검증했으면 영원히 보이지 않았다.
→ **상태 전이 근거로 "테스트 통과"를 쓰지 않는다.** §8 M4 의 CI exit code 선결 조건과 같은 이유다.

### M1 — 그림자 모드 ★ 가장 중요 — **구현 완료, 활성화 대기 (2026-09-14)**
- 산출: `loader.py` · `predicates.py` · `observer.py` · `simulate.py`, 테스트 117건
- **활성화는 사용자만 할 수 있다** — hook 등록은 `~/.claude/settings.json` 수정이고,
  이는 에이전트의 자기 수정에 해당해 harness 가 차단한다. 등록 조각은
  [m1-hook-registration.md](m1-hook-registration.md)
- 설치 전 측정으로 술어 결함 1건 제거: `test_unverified` 가 정탐 0 · 오탐 100% 였다
  (worktree 39/39 에 shim 이 존재하는데 명령줄에서 `-w` 를 찾고 있었다).
  판정을 "명령줄 플래그" 에서 "shim 라우팅 여부" 로 전환
- 기대 발화량: `allow_miss` 작업당 중앙값 3건 ([측정 0001](measurements/0001-allow-miss-baseline.md)).
  대부분 `plan_stale` 로 귀결될 것이므로 **판정 라우팅이 load-bearing 이다** —
  이 발화량이 전부 사람에게 가면 경보 예산을 첫날에 소진한다
- 술어를 돌리되 **아무것도 차단하지 않는다.** `audit/log.jsonl` 에 기록만 한다
- **계약 없는 deny 판정 (2026-10-19, [0004](decisions/0004-policy-deny-without-contract.md))**:
  레포 정책(`policies/<repo>.yaml`)의 `scope.deny` 는 계획 계약이 없어도 `deny_hit` 를 낸다
  (`allow_miss`·`escalate_hit` 는 계약 필요). 로그 `contract_source`(plan|policy|none)·
  `policy_deny`, `report` 에 별도 집계. worktree 에서도 메인 레포 이름으로 정책을 찾는다
- **hook 은 사용자 레벨(`~/.claude/`)에 등록한다.** 프로젝트 레벨 `settings.json` 은 gitignore 되어
  worktree 체크아웃에 존재하지 않는다 — 거기 등록하면 **43개 worktree 에서 아무것도 관측하지 못한 채
  "데이터 없음"을 "오탐 0"으로 오독**하게 된다. 근거 [0002](decisions/0002-m1-deployment.md)
- 종료 기준: **2주간 실측으로 오탐률 확보.** 사람 도달 경보 추정치가 예산(3회/일) 이하
- **데이터 부재 위험 (종료 판정 전 반드시 확인)**: 계약이 달린 계획이 하나도 없으면
  `allow_miss`·`deny_hit`·`escalate_hit` 는 한 번도 발화하지 않고 로그가 `has_contract:false`
  로만 쌓인다. **그 상태는 "오탐 0" 과 구분되지 않는다.**
  종료 판정은 반드시 `has_contract:true` 관측 건수를 먼저 보고, 0 이면 기간을 연장하거나
  `simulate.py` 로 과거 브랜치를 소급 재생해 보충한다.
  (같은 함정: 프로젝트 레벨 hook 등록 시 worktree 관측 0 — [0002](decisions/0002-m1-deployment.md))
- 근거: 오탐률을 **예상하지 않는다.** §2 의 부등식은 실측 없이 풀 수 없고,
  예상으로 집행을 켜면 첫 주에 경보 피로로 죽는다

### M2 — 술어 집행
- M1 에서 오탐 0 으로 확인된 술어만 차단으로 승격. 나머지는 그림자 유지
- 종료 기준: 경보 예산 준수 상태로 2주 유지

### M3 — escalation (감사 프로세스)
- 술어로 판정 불가능한 건만. 강도 3(모델 자가교정) 우선, 강도 2(사람)는 모호한 건만
- 종료 기준: 무개입 완주율이 M2 대비 상승

### M4 — FSM 루프 (선택)
- **선결: CI exit code.** 상태 전이 근거가 자기보고면 자동화는 신뢰의 부재를 반복하는 속도일 뿐

## 부록 — 이 설계가 기각한 것

README 「기각된 설계」 에 더해, 목적에서 연역되어 기각된 것:

| 기각 | 사유 |
|---|---|
| 탐지율을 목표 지표로 삼기 | 목적은 탐지가 아니라 주의 절약. 탐지율 상승이 순손실일 수 있음 |
| 처음부터 집행 모드로 시작 | 오탐률을 예상하게 됨. M1 그림자 모드가 대안 |
| 경보를 전부 사람에게 | 인간 속도 병목 재생산. 강도 3 우선 |
| 고장 시 안전을 위해 차단 (fail-closed) | 고장난 감사가 작업을 멈추면 목적에 정면으로 반함 |
| 계약 작성 강제 | 계획 회피 유인. 무계약은 조용히 폴백 |
