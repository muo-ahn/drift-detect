# 0001 — 공유 인프라 보호는 레포 기본 deny 가 아니라 escalation 영역으로 둔다

- 상태: **확정** (2026-09-11)
- 절차: 변호인 3인 병렬 변호 → 판정관 판결 → 호스트 사실검증
- 관련: `docs/design.md` §10 미결, `docs/spec/plan-contract-v1.md` §7 미결

---

## 쟁점

공유 인프라(`core/common/**`, `core/core/config/**` 등)에 대한 보호를 레포 수준 기본값으로 둘 것인가.

| 안 | 내용 |
|---|---|
| A | 레포 기본 **deny** 파일을 컴파일 시 계약에 병합 |
| B | 기본값 없음. 계약은 그 문서 안에서 완결 |
| C | 레포 기본값을 두되 **deny 가 아니라 escalation 트리거**. 저작 스키마는 2필드 유지하고 컴파일 산출물에만 병합 |

## 결정

**C안 골격 채택.** 저작 스키마(`scope.allow` / `scope.deny` 2필드)는 불변이고,
레포 기본값은 `contract.json` 산출물에 **별도 필드 `escalate_paths`** 로 병합한다.
`deny` 에 병합하지 않는다 — 차단이 아니라 판정 소집이다.

## 근거

### 실측이 A안을 기각했다 (Core-System, 최근 90일)

| 경로 | 병합 커밋 터치 | 비고 |
|---|---|---|
| `core/common/` | 57 커밋 | |
| `core/core/config/` | 16 커밋 | |
| **합계 (중복 제거)** | **211건 중 110건 = 52%** | |

공유 인프라 터치는 예외가 아니라 **과반의 routine** 이다.
`deny`(Tier 0 BLOCK)로 걸면 전체 작업의 절반이 즉시 차단된다 —
`design.md` §2 의 오탐 비대칭(오탐 → 경보 꺼짐 → 체계 사망)과 정면 충돌한다.

### 0건 항목은 전부 측정 오류였다 (호스트 사후 검증)

판정 과정에서 `Makefile`·`conftest.py`·`tests/_base.py` 가 90일간 0건으로 보고되어
"이것들만 hard deny 해도 안전하지 않은가" 라는 여지가 남아 있었다. **셋 다 무효다.**

| 경로 | 0건의 실제 원인 |
|---|---|
| `Makefile` | **의도적 미커밋 관행.** worktree 인식 로직이 담겨 있어 커밋하지 않는다. 측정 시점에도 45줄 추가/10줄 삭제가 미커밋 상태였다. 병합 커밋 기반 측정이 구조적으로 못 잡는 파일 |
| `conftest.py` | **레포에 존재하지 않는다.** 0건은 자명하게 참이고 정보량이 0 |
| `tests/_base.py` | **경로 오류.** 실제는 `core/tests/_base.py` 이고, 올바른 경로로 재측정하면 **211건 중 11건(5.2%)** |

→ **hard deny 자격을 갖는 경로는 하나도 없다.** A안의 잔여 근거가 소멸했다.

부수 발견: `Core-System/.claude/rules/05-code-review.md` 의 공유 인프라 목록에
존재하지 않는 파일과 틀린 경로가 포함되어 있다. A안이 이 목록을 "실측·검증된 선례" 로
인용했으나 검증된 적이 없었다.

### B안이 남긴 것

B의 최강 논거 — "계약 인플레 완화책은 *작업 전 사람 confirm 으로 고정* 인데,
레포 기본값을 몰래 병합하면 **confirm 한 문서 ≠ 집행되는 정책**이 된다" — 는 유효하다.
판결은 이를 기각하지 않고 **투명성 조건으로 흡수**했다 (아래 필수 조건 3번).

B가 잡아낸 **캐시 무효화 결함**(정책 파일 변경을 `contract.meta.json` 이 감지하지 못함)도
구현 조건으로 흡수했다.

## 기각 사유 (재제안 금지)

| 안 | 기각 사유 |
|---|---|
| **A** | 실측 52% 차단 → 오탐 비대칭 원칙 정면 위반. 더해 변호 과정의 인용이 파일 귀속 오류 다수, 사실오류 1건("계약 인플레가 기각 목록 1순위" — 실제로는 §9 리스크 표 항목) |
| **B** | 계약 인플레(`allow: [core/**]`)를 막을 구조가 없다. 미선언 경로 자동 escalation 만으로는 **계약이 넓게 선언된 경우**를 못 잡는다 — 그것이 레포 기본값의 유일한 존재 이유다 |
| hard deny 대상 축소안 (0건 경로만 deny) | 0건이 전부 측정 오류. 대상이 존재하지 않는다 |

## 필수 구현 조건

### M0 (컴파일러 C1)

1. ~~레포 기본값은 git 추적되는 별도 정책 파일에 둔다 (`.claude/policy/repo-escalation.yaml`)~~
   → **[0003] 으로 개정**: 대상 레포가 아니라 drift-detect 안에 레포별로 둔다 (`policies/<repo-name>.yaml`). 검토·버전 관리라는 목적은 유지하고 위치만 옮긴 것이다
2. `contract.json` 의 `deny` 가 아닌 **별도 필드 `escalate_paths`** 로 병합한다. 저작 스키마는 불변
3. `verdict.reason` 에 **트리거 출처**(계약 명시 / 레포 기본값)를 구분 표기한다 — B의 투명성 우려 완화
4. `contract.meta.json` 의 추적 대상에 **정책 파일의 mtime·해시를 포함**한다 — 누락 시 캐시 미갱신 결함
5. 레포 기본값 단독으로 "계약 있음" 을 만들지 않는다. 유효한 `allow` 가 있을 때만 병합한다 (무계약 비차단 불변식 보존)

### M1 이후

6. 강도(자가교정 vs 사람 소집)는 **지금 정하지 않는다.** 2주 그림자 모드 실측 후 결정
7. 초기 목록은 실측 hot path 우선 — `core/common/**`, `core/core/config/**`
