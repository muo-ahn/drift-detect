# 0002 — M1 배포는 외부 절대경로 참조로 한다

- 상태: **확정** (2026-09-14)
- 절차: 변호인 3인 병렬 변호 → 판정관 판결 → 호스트 사실검증
- 관련: `docs/design.md` §8 M1, §10 미결「배포 방식」

---

## 쟁점

M1 그림자 모드를 위해 `src/drift_detect/` 코드가 어떻게 실행되게 할 것인가.

| 안 | 내용 |
|---|---|
| A | 외부 절대경로 참조 — hook 이 `sys.path` 에 drift-detect 경로를 추가 |
| C | 중첩 submodule — `Core-System/.claude/vendor/drift-detect` |
| D | 벤더링 — 코드를 대상 레포에 복사해 커밋 |
| H | (호스트 제안 하이브리드) 사용자 레벨 **얇은 로더** + 레포에 벤더링된 payload |

## 결정

**M1 = A안.** H안은 **M2 승격 시점으로 예약.** C안은 **영구 기각.**

---

## 쟁점이 재정의된 지점 ★

세 변호인 모두 **"코드가 대상 레포에 닿아야 한다"** 를 전제했다. 이 전제가 틀렸다.

**hook 은 애초에 레포 밖에 산다.**

| 등록 위치 | PreToolUse | PostToolUse | 모든 worktree 에서 발화? |
|---|---|---|---|
| 사용자 레벨 `~/.claude/settings.json` | **5** | **4** | **예** |
| 프로젝트 레벨 `Core-System/.claude/settings.json` | 1 | 0 | **아니오** |

프로젝트 레벨 `settings.json` 은 `.gitignore:140` 의 `settings.json` 패턴에 걸려 **untracked** 이고,
worktree 체크아웃에 존재하지 않는다(2곳 확인).

그리고 이 프로젝트가 모범 사례로 삼는 `delegation_guard.py` 자체가 **이미 A안과 같은 방식**
(사용자 레벨 hook + 레포 밖 절대경로)으로 동작한다.

→ 쟁점은 "코드를 레포에 어떻게 넣나" 가 아니라 **"레포 밖 로더가 레포별 버전을 어떻게 찾나"** 였다.
그 질문에 답하는 것이 H안이고, M1 에는 아직 그 질문이 발생하지 않는다.

---

## 근거

### A 채택 — M1 의 산출물이 단 하나이기 때문

M1 의 산출물은 **술어 오탐률 실측치 하나**다(`design.md` §8).
sync 스크립트·sha 스탬프·리뷰 게이트를 지금 짓는 것은 **아직 정당화되지 않은 인프라**이며,
"오탐률을 예상하지 말고 측정하라"는 M1 자신의 논리를 배포 방식에서 위반한다.
(같은 논리가 [0001](0001-repo-escalation-paths.md) 의 "강도는 실측 후 결정" 조건이다.)

fail-open 도 A 가 가장 단순하다 — 실패 지점이 `try/except ImportError` 한 곳이다.

### C 영구 기각 — worktree 에서 무음으로 비워진다

`submodule.recurse` 미설정 상태에서 `git worktree add` 는 submodule 을 init 하지 않는다.
worktree 의 해당 디렉터리는 **빈 채로 남고, 경고도 없다.**

Core-System 은 worktree 가 **43개**이고 다수가 `.claude/worktrees/` 밖에 있다(`~/.cursor/worktrees/…`).
그 대부분에서 payload 가 조용히 사라지면 **M1 의 유일한 산출물인 오탐률 실측치가 오염된다** —
관측이 0인 것을 오탐이 0인 것으로 오독하게 된다.

이는 대상 레포 `CLAUDE.md` 가 이미 경계한 **"무음 오검증"** 과 동일한 패턴이다.
C 변호인 스스로 "미검증 추정" 이라 자인한 항목이었고, 판정관 재현으로 사실로 확인됐다.

> **검증 한계 (은폐하지 않고 기록)**: 호스트는 이 재현을 **독립적으로 확인하지 못했다** —
> 이 환경은 git 실행이 의도적으로 deny 되어 있다. 판정관의 재현 결과와 문서화된 git 동작에 의존한다.
> 다만 C 는 기각되고 채택안 A 에는 submodule 이 없으므로 판결 자체의 리스크는 낮다.
> 직접 확인하려면 격리된 디렉터리에서 submodule 을 가진 레포를 만들고 `git worktree add` 후
> 해당 디렉터리가 비는지 보면 된다.

### D 는 기각이 아니라 유보

"커밋된 파일은 worktree 에 자동 전파된다" 는 실측으로 확인됐다 —
git 추적되는 `.claude/agents/*.md` 가 worktree 에 실재한다.
유효한 논거이지만, 지금 sync 인프라를 지을 **실측 근거가 없다.** H안에 흡수해 M2 로 넘긴다.

---

## 쟁점이 아니었던 것

**import 비용.** 실측 결과 `drift_detect` 누적 import 11.6 ms, 대조군 `json` 4.95 ms.
세 안 간 유의차가 없다. 프롬프트에 제약으로 넣었으나 논증 가치가 없는 항목이었다.

**Python 호환성.** hook 은 `/usr/bin/python3` = **3.9.6**(시스템)으로 돈다.
해당 인터프리터에서 테스트 55/55 통과, 구문 오류 0 — 문제 없음.
단 이 사실은 `pip install -e` 변형을 배제한다(시스템 site-packages 오염).

---

## 변호인 공통 오류

세 변호인 모두 **worktree 개수를 과소 추정**했다 — 10~19개로 추정, 실제 **43개**.
그리고 셋 다 위 ★의 전제 오류를 공유했다.

---

## 필수 구현 조건

### M1

1. drift-detect 경로가 없으면 `try/except ImportError` 로 **계약 없음 폴백**. 작업을 막지 않는다
2. 절대경로는 **로더 진입점 한 곳에만** 하드코딩한다. 팀 배포 시 재검토 대상임을 주석으로 남긴다
3. 로더는 C1(컴파일러)·C2(술어)에서만 쓴다. C4(액추에이터)는 M1 에서 아무것도 차단하지 않으므로 무관
4. hook 은 **사용자 레벨**에 등록한다. 프로젝트 레벨에 등록하면 43개 worktree 에서 아무것도 관측하지 못한 채 "데이터 없음"을 "오탐 0"으로 오독하게 된다

### M2 승격 조건

2주 실측에서 술어 오탐 0 이 확정되면 **H안으로 전환**한다 —
사용자 레벨 얇은 로더 + `<repo>/.claude/vendor/drift_detect` 커밋 payload,
D 의 sync 스크립트 · sha 스탬프 · 리뷰 게이트를 흡수한다.

**C안은 이 레포에서 영구 재제안 금지.**
